# 小规模 Flat/HNSW 成本实验

实验日期：2026-10-30。结果适用于当时的源码快照与合成输入，不代表当前提交重测。

## Flat/HNSW 决策实验

从仓库根目录执行，无需 SIFT1M、模型或网络：

```powershell
cargo test --offline --bin index_decision_benchmark
cargo build --offline --release --bin index_decision_benchmark
python -B -s scripts/run_index_decision.py
```

默认比较 128、512、2048 条 32 维均匀合成向量，32 条独立查询，L2、k=5；图参数
`m=8`、`m_max=16`、`ef_construction=80`、层级概率 0.5，搜索预算 16/64。
Python 数据种子 20261030；JSON 输入转为 Rust f32，Flat/HNSW 使用完全相同输入和
度量。Flat 精确扫描后选择 top-k 并排序，作为金标，不依赖旧 SIFT 的全库 groundtruth。

每规模做三次独立进程/新图，变化插入排列；图的内部层级 RNG 固定为 42，不能称为三种
独立层级种子。三种算法单元的顺序按种子打乱。每单元先预热整组查询一次，再保存逐查询
延迟和实际 ID；P50/P95 用 nearest-rank。建图不含输入解析，Flat 无专门建图，仅有准备
开销。内存是整个 worker 的峰值 RSS（Windows 为峰值 Working Set），包含输入、分配器、
查询与图，并非纯索引大小，也不是图内存增量。

本机结果：27 格成功、0 格失败。下表 Recall 为三实例均值，其余为三实例中位数；
不把实例的 P95 中位数冒充全部查询合并后的 P95。CPU 为 Intel64 Family 6 Model 165，
系统、提交基底、源码/Cargo.lock、二进制、输入哈希和所有逐查询观测均在原始报告中。

|规模|算法 / ef|Recall@5|查询 P95 ms 中位数|构建 ms 中位数|峰值 MiB 中位数|
|---|---|---:|---:|---:|---:|
|128|Flat|1.0000|0.0071|0.003|8.96|
|128|HNSW / 16|0.9833|0.0254|7.725|9.09|
|128|HNSW / 64|1.0000|0.0339|7.612|9.11|
|512|Flat|1.0000|0.0280|0.004|9.27|
|512|HNSW / 16|0.8479|0.0250|62.931|9.63|
|512|HNSW / 64|0.9958|0.0628|62.417|9.66|
|2048|Flat|1.0000|0.0972|0.003|10.54|
|2048|HNSW / 16|0.7583|0.0384|403.593|11.71|
|2048|HNSW / 64|0.9771|0.0943|411.520|11.77|

在**这组小型合成工作负载**中，128 条时 Flat 更省成本；2048 条时小 ef 的速度收益
伴随明显召回损失，ef=64 的 P95 接近 Flat 且有约 0.4 秒建图成本。不能在召回不等时
宣称 HNSW 更好，也不能由此给出真实 embedding 的统一规模阈值。测量时间很短、查询少、
没有机器隔离或统计显著性结论；真实数据、多维度和大规模实验是后续扩展。
