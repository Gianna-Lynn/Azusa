## 测试对象与配置

- 与 BM25 基线相同的完整 DuRetrieval：100,001 段中文文本、2,000 条查询、9,839 条标注。
- BGE-small-zh-v1.5 固定版本，CLS pooling、查询指令、512 token 截断、GPU fp16 推理，
  归一化后保存为 512 维 float32；区别于项目默认 Qwen 模型配置。
- Azusa 当前本地源码快照的 HnswIndex，通过专用 loopback HTTP 实验服务调用。
  使用同一批向量与相同 Azusa Cosine 度量对照精确扫描，没有替换成第三方 HNSW。
- 同一张图：m=16、m_max=32、ef_construction=200、seed=42、层级概率 0.5，按语料顺序插入。
- 精确检索及 HNSW ef_search=100/200/400，各执行全部 2,000 条查询，统一返回 100 条。
- 建图约 **20.51 分钟**，段落编码约 **8.68 分钟**，批量查询编码约 **1.65 秒**。
  批量查询编码耗时不是单请求编码延迟或 P95。
- 7,768 段文本超过编码长度被截断，查询无截断。它是模型输入限制，不能隐藏。

## 主要结果

“证据 Recall”以数据集相关段落标注为金标；“近邻 Recall”以精确向量 top-k 为参考。
下表查询耗时使用预先缓存的查询向量，不包含编码或答案生成。

| 模式 | 证据 Recall@10 | nDCG@10 | 近邻 Recall@100 | 原生平均 ms | 原生 P95 ms | HTTP 客户端 P95 ms |
|---|---:|---:|---:|---:|---:|---:|
| 精确 Cosine | 0.7896 | 0.7729 | 参考排名 | 92.85 | 97.05 | 101.79 |
| HNSW ef=100 | 0.7862 | 0.7706 | 0.9086 | 5.83 | 7.65 | 12.92 |
| HNSW ef=200 | 0.7886 | 0.7723 | 0.9614 | 8.57 | 12.01 | 17.41 |
| HNSW ef=400 | 0.7895 | 0.7728 | 0.9861 | 11.04 | 14.92 | 20.34 |

补充：HNSW 的近邻 Recall@10 在 ef=100/200/400 时分别为 0.9877、0.99545、0.9981。
top-100 的近邻召回明显低于 top-10，并不矛盾：召回后面较远的候选通常需要更多探索。

在这一次固定配置实验中，ef=200 的证据 Recall@10 比精确检索低约 **0.09 个百分点**，
原生平均搜索约快 **10.8 倍**。ef=400 进一步接近精确排名，但查询耗时增加。
这可以证明当前 Azusa HNSW 在此真实中文文本向量工作负载下的有效性，不能推断所有模型、
数据集、随机种子和并发条件下都具有相同效果，也不能据此认定 ef=200 是通用最优参数。

## 与 BM25 的关系

[已有 BM25 基线](text-scale-results-20261110.md)的证据 Recall@10 为 0.5968、nDCG@10 为 0.5804。
本轮固定 BGE 模型的精确向量检索在相同数据与标注下，两项指标更高。但 BM25 沿用简单中文
单字分词，未进行分词、参数和倒排实现优化，不能归纳为“向量检索普遍优于 BM25”。
两个实验执行时间和实现方式不同，不直接使用两者延迟计算公平的算法加速比。
尚未运行同规模 RRF 或 rerank 对照。

近似搜索得到的相关性指标偶尔可以略高于精确向量检索，因为向量相似度排序不等于相关性
金标排序；精确检索仅对该向量度量精确，不是证据召回的理论上限。
